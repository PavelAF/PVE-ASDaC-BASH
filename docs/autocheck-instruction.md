# Инструкция: Автопроверка стендов

Автопроверка выполняется **отдельным скриптом** `autocheck_standalone.py`. Это самостоятельный инструмент: развёртывание стендов — через `PVE-ASDaC-BASH.sh`, проверка — через `autocheck_standalone.py`.

Скрипт собирает информацию с ВМ развёрнутых стендов по предопределённым командам и выводит сырой результат. Оценка правильности — на усмотрение преподавателя.

## Требования

- **Proxmox VE** с развёрнутыми стендами (пулы с ВМ)
- **QEMU Guest Agent** — установлен и запущен внутри ВМ (для `exec_agent`)
- **python3** — на хосте PVE (предустановлен на PVE 8+)

## Запуск

### Интерактивный режим

```bash
python3 autocheck_standalone.py
```

Скрипт предложит выбрать конфигурацию из папки `autocheck/`, группу стендов, стенды для проверки и путь для сохранения отчёта (при необходимости).

### С указанием конфига

```bash
python3 autocheck_standalone.py autocheck/09.02.06-2026_module1.conf
```

Поддерживается путь к локальному файлу или URL:

```bash
python3 autocheck_standalone.py http://url/check.conf
```

### Дополнительные аргументы

```bash
python3 autocheck_standalone.py autocheck/09.02.06-2026_module1.conf -g GROUP_ID -s 1,2-5 -o report.txt -v
```

| Аргумент | Описание |
|----------|----------|
| `-g`, `--group` | ID группы стендов (без выбора из списка) |
| `-s`, `--stands` | Номера стендов (например `1,2-5,8`) |
| `-o`, `--output` | Файл для сохранения отчёта |
| `-p`, `--parallel` N | Проверять одновременно N стендов (по умолчанию 1; при нескольких стендах в интерактиве спрашивается) |
| `-v`, `--verbose` | Подробный вывод (отображение сырых bash-скриптов в отчете, спиннеры ожидания, таймауты и т.д.) |
| `--no-interact` | Без интерактивных вопросов (если заданы группа и/или стенды) |

## Файлы конфигурации

### Расположение

Скрипт ищет папку `autocheck/` рядом с собой. Обычно:

```
./autocheck_standalone.py
./PVE-ASDaC-BASH.sh
./autocheck/
    ├── example.conf           # Пример формата
    ├── 09.02.06-2026_module1.conf
    └── custom.conf
```

Конфиг можно указать по локальному пути или URL (HTTP/HTTPS).

### Формат конфига

Файл `.conf` — bash-скрипт с переменными:

```bash
# Название автопроверки (отображается в заголовке)
autocheck_name='ДЭ 09.02.06-1-2026 Модуль 1'

# ВМ и способ подключения
#   exec_agent  — QEMU Guest Agent (qemu-guest-agent в ВМ)
#   exec_serial — serial console (socat + serial0)
autocheck_vms='
    ISP    = exec_agent
    HQ-RTR = exec_agent
    HQ-SRV = exec_agent
    HQ-CLI = exec_agent
'

# Проверки
check_1_name='Имя хоста'
check_1_vms='ISP HQ-RTR HQ-SRV HQ-CLI'
check_1_cmd_exec_agent='hostname -f 2>/dev/null; hostname'

check_2_name='IP-адреса'
check_2_vms='ISP HQ-RTR HQ-SRV HQ-CLI'
check_2_cmd_exec_agent='ip -br a'
```

### Переменные проверки

| Переменная | Описание |
|------------|----------|
| `check_N_name` | Название проверки |
| `check_N_vms` | Список ВМ через пробел (ISP, HQ-RTR, …) |
| `check_N_cmd_exec_agent` | Команда для ВМ с exec_agent |
| `check_N_cmd_exec_serial` | Команда для ВМ с exec_serial |

### Serial console (опционально)

Для ВМ с `exec_serial`:

```bash
exec_serial_prompt='[A-Za-z0-9._-]+[#>]'
exec_serial_timeout='3'
exec_serial_login='admin'
exec_serial_password='P@ssw0rd'

# Переопределение для конкретной ВМ (дефис → подчёркивание)
# HQ_RTR_serial_login='root'
# HQ_RTR_serial_password='toor'
```

## Маппинг ВМ

Имена ВМ из конфига (ISP, HQ-RTR, …) сопоставляются с полем `name` ВМ в пуле PVE. Имена должны совпадать.

## Как это работает

### exec_agent (Guest Agent)

1. **Пинг агента** — перед опросом каждой ВМ проверяется доступность Guest Agent
2. **Запись скрипта** — все команды для ВМ собираются в один скрипт и записываются на ВМ через `agent/file-write`
3. **Выполнение** — скрипт запускается одной короткой командой (снижает нагрузку на агент)
4. **Пауза между ВМ** — 3 секунды, чтобы не перегружать гипервизор

Для слабых ВМ (1 ядро) этот подход стабильнее, чем множество отдельных вызовов агента.

### exec_serial (Serial Console)

1. Скрипт подключается к UNIX-сокету serial console напрямую (без socat)
2. **Реактивная авторизация** — ожидание промпта/логина/пароля по паттерну вместо фиксированных задержек
3. **Пакетное выполнение** — все команды для ВМ выполняются в одной сессии (один логин)
4. **Параллельность** — все serial-ВМ стенда проверяются одновременно через asyncio

## Ошибки и решения

| Сообщение | Причина | Решение |
|----------|---------|---------|
| Guest Agent недоступен | Агент не отвечает на ping | Установить qemu-guest-agent в ВМ, перезагрузить ВМ |
| got timeout | ВМ перегружена, агент не успевает | Увеличить паузу, перезагрузить ВМ перед проверкой |
| ВМ не найдена в стенде | Имя ВМ в конфиге не совпадает с name в пуле | Проверить имена в конфиге и PVE |
| ВМ не запущена | ВМ выключена | Запустить ВМ |
| python3 не найден | Python3 отсутствует (exec_serial) | Установить python3 (на PVE 8+ предустановлен) |
| Серийный порт не найден | serial0 не настроен для ВМ | Добавить serial port в настройках ВМ PVE |
| Консоль не отвечает | ВМ не отвечает через serial | Проверить настройку serial console в ВМ, увеличить timeout |
| Авторизация не удалась | Неверные логин/пароль для serial | Проверить exec_serial_login/password в конфиге |
